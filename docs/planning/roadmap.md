# Roadmap

Stages are ordered hypotheses, not promised release dates.

| Stage | Deliverable | Gate to advance |
| --- | --- | --- |
| Discovery | Agency audit, TTD reuse assessment, automatic publication policy and cost envelope | Feasible sources and an operator are identified |
| MVP beta | Reliable meeting timeline, cited agenda summaries, participation links, automatic validation, a shared topic catalog, and filters within meetings | Core task success and trustworthy publication and useful repeat visits across all three agencies over two meeting cycles within budget |
| Retention | Opt-in topic alerts, better matching, and calendar export | Users return and request follow-up; freshness and workload are sustainable |
| Broader access | More agencies, search, guides, translation | Existing coverage is reliable; demand and operating capacity justify each addition |
| Participation experiments | Bookmarks, polling, comment assistance, moderated discussion | A specific user need, an operating owner, and appropriate consent/moderation workflows exist |

Expand one agency at a time. Evaluate source maintenance cost as well as audience demand. Advocacy is a separate product decision, not an automatic stage of maturity.

At each beta cycle, review user feedback, missed/late meetings, correction count, operator time, and cost. Choose the next smallest useful improvement. Record the choice in the decision log and update linked idea statuses.

The local October 2026 iteration adds a shared topic catalog, meeting-level filters, and single-event calendar downloads before any cloud launch. Keyword search over captured agenda text and capture of the linked Truckee HTML agendas are the next proposed local candidates; accounts and subscription alerts remain deferred.

Implementation uses the [selected stack](../decisions/0005-selected-stack.md); service selection is complete. The discovery stage now validates source coverage and processing feasibility, not a new vendor comparison.
